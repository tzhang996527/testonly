你是一个专业的软件工程师，根据下面的系统设计，设计一个专业的系统，创建UI，数据采用mock数据，设计mock api，后续用真实api替换。系统需求如下。

评估系统设计

一、总体流程
评估立项 → 前期工作 → 清查盘点 → 资料收集 → 评定估算 → 内部审核 → 结果确认 → 报告归档 → 后续跟踪
 
二、分环节详细流程
1. 评估立项
目的：锁定评估目的、范围、基准日、负责人，作为唯一流程入口。
•	创建评估立项单
o	关键字段：评估单号、评估目的、评估基准日、资产类别（固资 / 无形 / 存货 / 整体资产）、负责人、审批流
•	审批：部门→风控→办公室→总经理
•	涉及底稿：基本情况表，独立性审核，风险评价表
•	ERP 状态：草稿→已审批→执行中
2. 前期工作
目的：预沟通，避免线下线下脱节。
•	签订业务委托合同、提供资料清单、制定评估计划
•	审批：部门→办公室→总经理
•	涉及底稿：业务委托书，资料清单，评估计划表
•	ERP 状态：合同已签，清单已锁定，人员安排已完成
3. 资产清查与现场盘点
目的：通过询问、引用审计函证、核对、监盘、勘查、检查等方式进行调查，了解评估对象现状，关注评估对象法律权属；对不宜进行逐项调查的，根据重要程度采用抽样等方式进行调查。对被评估单位收益状况进行调查：评估专业人员主要通过收集、分析企业历史经营情况和未来经营规划以及与管理层访谈对企业的经营业务进行调查。 
•	现场核查、录入盘点结果、生成盘点差异表，财务 + 技术部门双签字，生成评估申报表
•	完成现场勘察记录完成、访谈记录
•	涉及底稿：评估明细表，各科目工作底稿
•	ERP 状态：盘点完成→差异待处理→差异已处理
             评估明细表，各科目工作底稿已录入
                 访谈记录已上传
4. 资料收集与建档
目的：评估专业人员从市场等渠道独立获取资料，从委托人、被评估单位等相关当事方获取资料，以及从政府部门、各类专业机构和其他相关部门获取资料。 评估专业人员对资产评估活动中使用的资料采取适合的方式进行核查验证，核查验证的方式通常包括观察、询问、书面审查、 实地调查、查询、引用审计函证、复核等。
•	必收集资料（上传至 ERP 附件，支持在线预览 / 下载）：
o	权属证明：产权证、行驶证、专利证、商标证、购置发票、合同
o	财务资料：台账、折旧表、审计报告、近 3 年财报、盈利预测
o	技术资料：图纸、说明书、维修记录、检测报告
o	外部资料：市场报价、可比交易案例、行业数据
•	ERP 状态：资料收集完成
5. 评定估算
目的：1、 根据评估目的、评估对象、价值类型、资料收集等情况，分析市场法、收益法和资产基础法三种资产评估基本方法的适用性，恰当选择评估方法；2、 根据所采用的评估方法，选取相应的公式和参数进行分析、计算和判断，形成合理评估结论。 
在 ERP 录入评估方法与结果，支持系统自动计算或人工录入。
•	系统自动计算评估值；或人工录入外部评估机构结果
•	生成评估明细表：资产编号、原值、净值、评估值、增减值、增值率
•	ERP 状态：初步评估完成
6. 多级审核（ERP 模块：审批流 / 工作流）
目的：确保评估结果合规、准确、无风险。1、 评估专业人员在评定、估算后，形成初步评估结论，按照法律、行政法规、资产评估准则的要求编制初步资产评估报告；2、 根据资产评估机构内部质量控制制度，对初步资产评估报告进行内部审核； 3、分公司根据内部管理制度进行授权审核。
•	一级：部门负责人（数据准确性）
•	二级：总师室
•	三级：总经理 / 授权人（最终审批）
•	涉及底稿：评估报告，评估说明，三审单，重大问题处理结果
•	ERP：支持串行 / 并行审批，驳回可修改重提，全程留痕
•	ERP 状态：审核中→审核通过→已驳回
7. 评估结果确认与发布（ERP 模块：评估结果主数据）
目的：锁定最终评估值，作为后续账务与报告的唯一依据。
•	在不影响对评估结论进行独立判断的前提下，与委托人或者委托人许可的相关当事人就评估报告有关内容进行沟通，对沟通情况进行独立分析并决定是否对资产评估报告进行调整； 
•	生成评估结果确认单（ERP 正式单据）
o	关键字段：评估单号、资产编号、原值、净值、评估值、增减值、评估方法、评估机构（如外部）、评估师、报告编号
•	确认单审批通过后，系统锁定结果，不可随意修改（修改需走变更流程）
•	涉及底稿：委托方意见反馈表
•	ERP 状态：结果已确认→正式生效
8. 评估报告与归档（ERP 模块：文档管理 / 报表）
目的：生成正式报告，资料归档，满足审计与合规要求。资产评估机构及其评估专业人员完成以上评估程序后，向委托人出具并提交正式资产评估报告。
•	系统生成评估报告（模板化，含明细表、汇总表、说明）
•	报告审批、盖章（电子签章）
•	全套资料归档至 ERP：
o	立项单、清单、盘点表、差异表、权属资料、计算表、审核记录、确认单、凭证、报告
•	归档后不可删除，仅可查阅 / 导出，保存期限合规
•	涉及底稿：委托方签收单
•	ERP 状态：报告已出具→归档完成
9. 后续跟踪反馈
目的：评估后持续监控报告使用情况。
 
三、ERP 信息化核心要点
1.	主数据统一：资产编号唯一，台账完整，字段标准化（名称、规格、型号、位置、权属号）。
2.	流程可配置：评估目的、审批流、评估方法、凭证模板可配置，适配不同资产类型与业务场景。
3.	全程留痕：所有操作（创建、修改、审核、驳回、归档）记录人 + 时间 + IP，支持追溯。
4.	集成闭环：资产台账→盘点→评估，数据自动流转，减少手工录入。
5.	权限控制：按角色分权（评估专业人员、评估师、部门经理、总师室、总经理），敏感数据（评估值、权属资料）权限隔离。
